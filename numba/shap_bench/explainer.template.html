The expensive temporary is only 13 bytes

Original helper · array expression

@njit
def _mask_delta_score(m1, m2):
    return (m1 ^ m2).sum()

Optimized helper · fused reduction

@njit(inline="always")
def _mask_delta_score(m1, m2):
    score = 0
    for i in range(len(m1)):
        score += m1[i] ^ m2[i]
    return score

Evidence, capture limitations, and reproducibility

This view reconstructs the two existing flamegraphs from original.folded and optimized.folded. Stack paths and weights are unchanged. Colors are assigned by function family; unresolved labels are preserved.

  • Units: perf sampled cpu_core/cycles/P at 499 Hz. Folded values sum sampled event periods (cycle weights): 44,609,024,343 original and 42,514,740,819 optimized. The old SVG's “samples” unit was the renderer default, not a literal count of samples.
  • Symbols: [perf-895270.map]_[j] is an unresolved JIT mapping, not a resolved function. Its flat report contains hot instruction addresses without function names. Some stack paths are incomplete or include suspicious heap/unknown frames. Zero lost samples does not guarantee correct unwinding or symbolization.
  • Scope: delayed recording aimed to skip warm-up. The files still contain a small amount of interpreter shutdown and compiler-related activity; the recording window was not gated precisely around only warmed calls.
  • Variants: perf_driver.py preserves the original XOR expression but forces score-gain/reversal helper inlining. It is not a byte-for-byte upstream baseline. Both captures enabled NUMBA_ENABLE_PROFILING=1 and NUMBA_DEBUGINFO=1, which can affect generated code.
  • Causality: allocation/free stacks are observed; the temporary array is confirmed independently in LLVM. This capture cannot assign the unnamed JIT cycles to XOR, sum, reference counts, or other instructions. It cannot by itself explain the entire 32× timing difference.
  • Absence: no NRT allocation/free frames were sampled in the optimized capture. That does not mean the function performs no allocations: it still creates its output array.

Host: Intel i7-14700, CPU 2; Linux 6.8.0-139-generic; Python 3.12.3; Numba 0.67.0; llvmlite 0.49.0; NumPy 2.5.3; perf 6.8.12. Both final captures reported zero lost samples. Raw data remains on the Linux host under /tmp/shap_bench_codex/.

A stronger next profile would resolve JIT symbols, gate sampling after warm-up and before shutdown, compare an exact upstream baseline, and measure runtime without profiling flags.
